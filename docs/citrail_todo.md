## 1. パスファインダーへの複数ノード選択方法の改善（2026-07-25 セッション、相談・仕様確定・未実装）

**現状の課題**：Citrailからパスファインダーへノードを送る際、現在は「ノードをクリック→詳細パネルを開く→チェックボックスでパスファインダー送信対象にする」という操作を1件ずつ繰り返す必要があり、複数ノードを送りたいときに手間がかかる。

**検討の経緯**：まず「Ctrl(Cmd)+クリックでのトグル選択＋Ctrl+ドラッグでの範囲選択」という案を提示したが、Yujinさんからの代案（以下）を採用することになった。

**採用する仕様（確定・未実装）**：
1. 専用ボタン「パスファインダーに送るためのノードを選択」をクリックすると、選択モードに切り替わる
2. 選択モード中は、キャンバス全体にうっすら色を重ねて（背景色調を変更するなど）、通常モードと視覚的に区別できるようにする
3. 選択モード中は「選択モード中：◯件選択済み」のような件数表示を常に出す
4. 選択モード中にノードをクリックすると、**詳細パネルは開いたまま**にし（内容を見ながら選ぶ必要があるため）、それと同時にそのノードのパスファインダー送信対象のON/OFFも切り替える（📌マークで選択状態を表示。既存の`togglePf()`/`pfSelection`の仕組みをそのまま流用できる想定）
5. 「パスファインダーに送る」ボタンをクリックすると、これまで通り送り先の地図（新規作成／既存の地図から選択）を選ぶモーダルを経て、新しいタブでパスファインダーが起動する。送信後、Citrailは自動的に通常モードへ戻る
6. 専用の「キャンセル」ボタンを用意し、これを押すと送信せずに通常モードへ戻る。**仕様確定**：キャンセルしても、それまで選択モード中に選んだ📌(パスファインダー送信対象)はそのまま維持する(解除しない)。「パスファインダーへ送る」ボタン自体は常時表示のため、キャンセル後でも送信操作は引き続き可能
7. **仕様確定**：Escapeキーでのキャンセルは実装しない(専用のキャンセルボタンのみ)

**技術的な実装方針(確認済み)**：
- ノードタップ時の処理(`graph.js`の`onSelect`コールバック、現状`p => { renderPanel(p); openPanel(); }`)に、選択モード中なら`togglePf()`も呼ぶ処理を追加するだけでよく、詳細パネルを開く既存の挙動は変更しない
- 選択状態の表示(📌マーク)・件数表示付きの送信ボタン(`#btn-pf-send`)・送信処理(`sendToPathfinder()`)は既存の仕組みをそのまま流用する

## 2. 実装完了（2026-07-25 セッション、続き）

上記「1.」の仕様通りに実装した。

- `index.html`：ツールバーに「🧭 送るノードを選択」ボタン(`#btn-pf-select-mode`)、「選択モード中：◯件選択済み」の件数表示(`#pf-select-status`/`#pf-select-count`)、「選択モードを終了」ボタン(`#btn-pf-select-cancel`)を追加(後者2つは選択モード中のみ表示)
- `style.css`：`body.pf-select-mode`時に`#cy-wrap`へ`::before`疑似要素でうっすら色を重ねるルールを追加(`pointer-events:none`でクリックは奪わない)。件数表示バーのスタイル(`.pf-select-status`)も追加
- `app.js`：`pfSelectMode`という状態変数を追加し、`Graph.init`の`onSelect`コールバックで「選択モード中なら`togglePf()`を呼んでから`renderPanel()`する」処理を追加(**この順序が重要**：先に`renderPanel()`してから`togglePf()`すると、詳細パネルのチェックボックスが古い状態のまま表示されてしまう不具合があったため、必ずtogglePfを先に呼ぶ)
- `panels.js`：`setPfSelectMode(on)`関数を新設し、モードのON/OFFに応じて上記のボタン・件数表示の表示切替を行う。`updatePfSendButton()`は件数表示(`#pf-select-count`)も同時に更新するよう拡張。「パスファインダーへ送る」の確定ボタン(`#pf-target-ok`)のクリック処理に、送信後`setPfSelectMode(false)`を呼ぶ処理を追加(送信後は自動的に通常モードへ戻る)
- キャンセルボタン(`#btn-pf-select-cancel`)は`setPfSelectMode(false)`を呼ぶだけで、`pfSelection`自体はクリアしない(選択内容を維持する仕様通り)

Playwrightで、選択モードへの切替・キャンバスの色重ね・件数表示・ノードタップでの選択トグル(詳細パネルは開いたまま)・別ノードへの切替・キャンセル後の選択維持・選択モード外でのタップが選択に影響しないこと・送信後の自動モード解除、をそれぞれ確認済み。既存のCitrail連携の回帰テスト(新規タブ・送り先地図指定・重複防止・被引用数の受け渡し)もすべて通過を確認済み。
